# AI 感が出るパターンと、その代わりに取る形

ここに挙げる見た目の数値（文字サイズ・余白・角丸・色の値・動きの時間）は、プロジェクトに既存のデザインシステムが無いときの出発点として使う。既存のトークンや画面と食い違うなら、既存の側に従う。

WCAG 2.2 のレベル AA は別で、既存の値より優先する（SKILL.md の「判断の優先順位」）。項目に添えた達成基準番号は、該当する基準を探す手がかりとして使う。既存のトークンが基準を満たさないなら、そのトークンを直す。

## タイポグラフィ

文字の大きさと太さの差は、情報の階層を伝える最も安い手段になる。差が小さいと、読み手はどこから読めばよいか分からない。

| 避ける                                         | 代わりに取る形                                                                         |
| ---------------------------------------------- | -------------------------------------------------------------------------------------- |
| 見出しと本文の大きさの差が小さい（24px と 16px） | 画面の主見出しは本文の 2 倍以上にし、段階を 4〜5 個に絞る                              |
| 太さが 400 と 700 の 2 種類だけ                | 400 / 500 / 600 などから 3 段階を役割ごとに割り当てる                                   |
| 大きな見出しも本文と同じ字間                   | 欧文の大きな見出しは字間を詰める（-0.01em〜-0.03em 程度）。和文は一律に詰めると字が接するので、`font-feature-settings: "palt"` でかなの字幅を詰めるに留める |
| 行間が全部同じ                                 | 見出しは 1.2〜1.3、本文は 1.5〜1.7。日本語の本文は欧文よりやや広め                        |
| 数値の桁がそろわない                           | 表や金額など並べて比べる数値には等幅数字（`font-variant-numeric: tabular-nums`）を使う |

フォントは、日本語を含むなら日本語の字形が整ったもの（Noto Sans JP、BIZ UDPGothic など）をプロジェクトに合わせて選び、フォールバックを必ず指定する。

## 色

色は「注目させたい場所」を示す信号として使う。多くの場所に強い色を使うと、信号が意味を失う。

| 避ける                                           | 代わりに取る形                                                                     |
| ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 紫系のグラデーションと白背景の組み合わせ         | 製品の性格から主色を 1 つ決め、グラデーションは役割があるときだけ使う              |
| 原色をそのまま使う                               | 彩度を少し落とした色を基準にする                                                   |
| 背景が純白・純黒、文字が純黒・純白               | ライトは背景 #FAFAFA・本文 #1A1A1A 程度、ダークは背景 #0F0F10・本文 #EDEDED 程度にしてぎらつきを抑える |
| 無彩色のグレーだけで面を分ける                   | 主色や暖色・寒色をわずかに混ぜたグレーを使う                                       |
| 強調色を見出し・アイコン・枠・ボタンに散らす     | 強調色は主操作と状態表示（エラー・警告など）に限る。1 画面で強調色を使う箇所を数えて絞る |
| 文字と背景のコントラストが足りない               | 本文は 4.5:1 以上、大きな文字（18.66px 以上の太字か 24px 以上）は 3:1 以上にする（WCAG 1.4.3）。値はトークンから計算して確かめる |
| 状態を色だけで伝える                             | 色の見分けにくい人には読めないため（WCAG 1.4.1）、アイコンか文字のどちらかを併用する |

## レイアウトと余白

余白は「何と何が仲間か」を伝える。近いものは関係があり、離れたものは別のまとまりだと読まれる。

| 避ける                                       | 代わりに取る形                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------- |
| すべて中央揃え                               | 左揃えを基本にし、中央揃えはファーストビューや単独の主操作に限る                      |
| 余白の値がばらばら、または全部同じ           | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 のような段階を決め、要素間 < グループ間 < セクション間 にする |
| 同じ大きさのカードを等間隔に並べるだけ       | 重要度で大きさや位置を変える。全部が同じ重さなら、カードにせず一覧にできないか考える |
| カードの中にカード、枠の中に枠               | 囲みは 1 段に留め、内側の区切りは余白で表す                                           |
| 文章の行が画面幅いっぱいに伸びる             | 本文の幅は 1 行 35〜45 文字（欧文なら 65ch 前後）に収め、コンテナにも最大幅を決める |

## ラベル・説明文

画面上の文字は、読み手が 1 つずつ処理する。意味の無い文字が増えるほど、必要な文字が埋もれる。

| 避ける                                                                                   | 代わりに取る形                                                                 |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 見出しを言い換えただけのサブタイトル（「通知設定」の下に「通知に関する設定を変更できます」） | 見出しの語を具体的にし、サブタイトルは消す                                     |
| 並びや見出しから種類が読める値に、毎回「件数」「日時」とラベルを添える                   | 列見出しやグループ見出しで 1 回だけ示す                                         |
| ラベル・placeholder・ヘルプテキストで同じことを書く                                      | 見えるラベルは残し、placeholder とヘルプテキストからラベルと同じ内容を消す     |
| セクションの冒頭に「ここでは〜を表示します」                                             | 消す。中身を見れば分かる                                                       |
| 色・アイコン・文字の 3 つで同じ状態を示す                                                 | 色に加えるのはアイコンか文字のどちらか 1 つにする。アイコンの意味が一般的でないなら文字を選ぶ。状態を表すアイコンには読み上げられる名前を付ける（WCAG 1.1.1） |
| 「送信」「OK」など、何が起きるか分からない汎用の動詞をボタンに書く                       | 操作の結果を言う（「予約する」「保存して続ける」）。ボタンの文字を具体的にすると、周りの説明文を消せる |

説明を足したくなったら、先にレイアウトで直せないかを考える（並べ替える、グループを分ける、見出しの語を変える）。残すかどうかは「そのラベルを消した画面を初見の人が見て、意味を取り違えるか」で決める。

次は、この節の原則にかかわらず残す。

- 入力欄の見えるラベル、必須かどうか、入力形式の制約、単位：入力中は placeholder が消えるため、ラベルが見えないと何を入力しているか分からなくなる（WCAG 3.3.2）
- 取り消せない操作・課金・データ消失など、誤解したときの損失が大きい箇所の説明
- 画面から消したラベルのうち、支援技術に必要なもの：`aria-label` や視覚的に隠したテキストで残す（WCAG 4.1.2）

配置で表したまとまりと階層は、マークアップでも表す。見出しは見出し要素、並びはリスト、表の列見出しは `th`、入力のまとまりは `fieldset` と `legend`、名前の付いた領域は `aria-labelledby` で示す。画面を読み上げで使う人には配置が見えないため（WCAG 1.3.1）。

## 部品の形

角丸・影・枠線を全部同じにすると、部品の役割の違いが見えなくなる。

| 避ける                               | 代わりに取る形                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------------- |
| 角丸がすべて同じ値                   | 外側ほど大きく（カード 12〜16px、ボタン 8px、入力 6px など）。入れ子では内側を小さく |
| 影がすべて同じ強さ                   | 浮いている度合いで分ける（ポップオーバーは強く、カードは弱く、平面の要素には付けない） |
| 濃い枠線で面を区切る                 | カードや区切り線など面を分ける枠線は 1px、背景に近い薄い色にし、余白で足りないときだけ使う。入力欄・チェックボックスなど部品を識別するのに必要な境界は、隣接色に対して 3:1 以上にする（WCAG 1.4.11） |
| アイコンが文字と大きさ・線の太さで合わない | アイコンは隣の文字の高さに合わせ、1 つのアイコンセットに揃える                 |
| アイコンだけのボタンに説明が無い     | アイコンだけのボタンには必ず `aria-label` で名前を付ける（WCAG 4.1.2）。意味が一般的でないアイコンは、さらに文字かツールチップを添える |

## インタラクションとモーション

動きは「何が変わったか」に目を向けさせるためにある。理由の無い動きは、操作の邪魔になる。

| 避ける                                        | 代わりに取る形                                                                    |
| --------------------------------------------- | --------------------------------------------------------------------------------- |
| どの要素も hover で浮き上がる・光る           | hover は押せることが伝わる最小の変化（背景色の 1 段階など）に留める               |
| すべての transition が 0.3s ease              | 小さな要素は 100〜150ms、大きな面は 200〜300ms。出現は ease-out、退場は ease-in   |
| 幅・高さ・位置（`width` `top` など）を動かす  | 大きさと位置の変化は `transform` で表す。レイアウトの再計算が起きず滑らかになる。色や背景色の小さな切り替えは動かしてよい |
| 読み込み時に全要素がふわっと現れる            | 操作の結果として変わった部分だけを動かす                                          |
| 動きを減らす設定を無視する                    | `prefers-reduced-motion` で動きを止めるか弱める。動きで酔う人がいるため。レベル AAA の基準（WCAG 2.3.3）なので既定の推奨として扱い、既存のデザインシステムが別の扱いを決めているならそちらに従う |
| フォーカスの見た目を消す                      | `:focus-visible` で、隣接色とのコントラスト比が 3:1 以上のリングを出す（WCAG 2.4.7 / 1.4.11） |

## 空・読み込み中・エラーの状態

ここは利用者が「次に何をすればよいか」を一番知りたい場面で、作り込みの差が最も出る。

| 避ける                                     | 代わりに取る形                                                                  |
| ------------------------------------------ | ------------------------------------------------------------------------------- |
| 空の状態が「データがありません」だけ       | 何が無いのかを具体的に言い、次の操作を 1 つだけ置く                              |
| 読み込み中は画面中央のスピナーだけ         | 読み込み後の配置と同じ形のスケルトンにし、表示されたときに位置がずれないようにする |
| エラーが技術用語（「500 Internal Server Error」） | 何ができなかったかと、利用者が次にできることを書く                            |
| エラーを画面上部にまとめて出すだけ         | 原因になった入力のすぐそばに出し、`aria-describedby` と `aria-invalid` で入力に結び付ける（WCAG 3.3.1 / 1.3.1）。項目の多いフォームは、上部に各入力へのリンク付きの一覧も置く |
| エラーが出ても読み上げられない             | 送信結果のように操作の後で現れるメッセージは、ライブリージョン（`role="alert"` など）で通知する（WCAG 4.1.3） |
| 破壊的な操作がワンクリックで実行される     | 確認を挟むか、取り消しを用意する                                                 |
