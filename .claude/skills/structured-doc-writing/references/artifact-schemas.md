# 成果物の書式

CLIが作るテンプレートを正とする。この文書は、各欄で決める内容を説明する。

## brief.md

- **読者**：この文書を読む役割と、読者が持っている前提知識
- **読後の状態**：読者が読み終えた時点で理解または判断できること
- **文書の問い**：文書全体が答える一つの問い
- **対象範囲**：本文で扱う内容
- **対象外**：関連していても本文では扱わない内容
- **制約**：推測禁止、文量、文体、公開範囲など

## evidence.md

一行に一つの事実を置く。

| 項目   | 内容                                      |
| ------ | ----------------------------------------- |
| ID     | 文書内で参照する安定した識別子。例：E-001 |
| 事実   | 出典から確認できた内容。解釈を混ぜない    |
| 出典   | URL、ファイル、クエリ、ユーザー発言など   |
| 確実性 | 確認済み、要確認、推定のいずれか          |
| 備考   | 集計期間、定義、比較条件など              |

事実から導いた計算結果は、入力となる根拠IDと式を記載する。

## outline.md

各章を次の単位で設計する。

```markdown
## section-id：章名

読者の問い：

この章の結論：

情報の序列：

- 最重要：この章で最も強く伝える事実または主張
- それを支える情報：最重要事項との関係が説明できる情報
- 補足：なくても結論は変わらないが、理解を助ける情報

使用する根拠：

- E-001

この章に書かないこと：

前後の章との関係：
```

「この章に書かないこと」は、隣接する章との責務の重複を防ぐために書く。

情報を同じ重さで列挙しない。複数の活動や事実を扱う章では、何を特に重視したかを決め、残りの情報が「その重点を実現する手段」「並行して進めた事項」「背景」のどれに当たるかを明記する。関係を説明できない情報は、その章から外すか補足へ下げる。

## sections/<section-id>.md

一つのファイルには一つの章だけを書く。章の冒頭で結論と最重要事項を示し、`outline.md`で割り当てた根拠だけを使う。別の章の説明が必要なら、その章の内容を複製せず参照する。

形式は情報の役割に合わせる。

- 段落：結論、評価、因果など、一続きの論旨を伝える。
- 箇条書き：重点、手段、内訳、実施事項など、親子関係のある情報を短く示す。親項目に論点を置き、子項目はその具体化に限る。
- 表：同じ定義・期間で複数の数値を比較する。

箇条書きを段落の代わりに細切れに使わない。見出し、親項目、子項目の順に読むだけで、「何を重視したか」「そのために何をしたか」「何を並行したか」が分かる構造にする。文書の元資料に簡潔な定型がある場合は、その情報密度と階層の深さを参考にする。

## review.md

次の順でレビュー結果を記録する。

1. **構造**：読者の問いに答える順序、章の責務、重複、欠落
2. **根拠**：主張と根拠IDの対応、定義、比較条件、事実と推測の区別
3. **可読性**：一文一義、用語、段落、表、冗長な表現

指摘には対象箇所、問題、根拠、修正方針、採否を含める。
