# design-improvement スキルの eval

`design-improvement` スキルを編集したら、このディレクトリの eval を回し、改善後のコードが初見の読み手に正しく読まれるかを確かめる。

## 回し方

`fixtures/` のコードを題材にし、シナリオごとに新しい文脈のサブエージェントを 2 段で使う。

1. **改善役**：`SKILL.md` を読ませてスキルに従わせ、題材の改善後コードと報告を書かせる。元の題材ファイルは編集させない
2. **読み手**：改善役とは別の新しいサブエージェントに、改善後のコードファイルだけを渡し、`SKILL.md` の「測る：読み手テスト」と同じ質問に答えさせる。報告やスキルは渡さない

採点は、読み手の回答と改善役の報告を [`scenarios.md`](./scenarios.md) の pass 基準に照らして行う。採点者は人間か、さらに別のエージェントにする。

## Pass 条件

- 各シナリオの pass 基準をすべて満たす
- 落ちたら、落ちた原因を `SKILL.md` に還元して再度回す。題材やシナリオの基準を緩めて通さない

## シナリオを足すとき

スキルに新しい判断基準を入れたら、それが効かないと読み手が誤読する題材を `fixtures/` に足し、`scenarios.md` に pass 基準を書く。題材は特定のプロダクトやサービスに依存しない汎用な内容にする。
