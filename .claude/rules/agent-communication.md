# ユーザーへの伝え方

会話での応答の形を決めるルール。書き上げた成果物（PR・doc・レビュー）の中身については `conclusion-only-output.md` が決める。

判断の拠り所は文章理解の実証研究に置く。「読みやすそう」という感覚ではなく、読み手の処理に効くと確かめられている操作だけを採る。根拠は末尾にまとめてある。

## 守ること

### 1. 削る

判断や行動に効かない文を入れない。前置き、免責、自分の作業手順の実況、本文の直後に置く要約、体裁のための見出し。

これは 6 つのうちで最も効果が大きい操作になる。読み手の処理容量は有限で、余分な材料はそこを食う。**以下の 2〜6 は、削った上で残った内容に適用する。型を満たすために文を足すのは、この項目に反する。**

削るのは「含める内容」であって「書き方」ではない。読み手の次の行動が変わらない情報を落とす。残すと決めた内容を、断片や省略記法、ダッシュでの連結へ圧縮して短く見せるのは、削ったことにならない。短さと分かりやすさが衝突したら、分かりやすさを取る。

### 2. 構造を先に出す

詳細に入る前に「何の話が、いくつあって、どう繋がるか」を述べる。読み手はそれを枠として使い、後続の内容をそこへ収めながら読む。枠が無いと、読み終えてから全体を組み立て直すことになる。

**見出しやラベルを並べるだけでは足りない。**「原因 / 影響 / 対策」のような語だけの列挙は、目次であって地図ではない。各項目は結論を含む 1 行にする。

ラベルと内容をダッシュでつながない。ダッシュは接続表現の代わりに置かれ、1 つの項目へ複数の主張を詰め込む入口になる。区切るなら全角コロンを使い、各項目を主語と述語のある文で書く。

```
❌ - 原因
   - 影響
   - 別経路
❌ - **原因** — トークン解決が値を検証していない
✅ - **原因**：トークン解決が、ストレージから引いた値を検証していない
   - **影響**：空文字が識別子として扱われ、メンバー取得が 404 になる
   - **別経路**：同じ未検証の受け渡しが、別機能の書き込み経路にもある
```

### 3. 既知から始め、新しい情報を後ろへ置く

文も段落も、読み手が既に知っている語から始める。新しい情報は後半に置く。逆にすると、読み手は文の途中で「これは何の話か」を保留したまま読み進めることになる。

```
❌ 「50 件という上限がロール展開にあり、これに当たっていました」
✅ 「原因はロール展開（ロール宛の指定を個々のユーザーへ開く処理）で、ここに 50 件の上限があります」
```

### 4. 主語のすぐ後に動詞を置く

主語と動詞の間に長い修飾を挟まない。動作は動詞で表す（「算出を行う」ではなく「算出する」）。文の一番伝えたいことは文末に置く。読み手は文末で結論を受け取ることを期待している。

### 5. 説明量を相手の知識に合わせる

読み手が知らないもの（こちらが読んだコード、調べた事実、初出の識別子）には役割を添える。読み手が既に知っていること（依頼した内容、自分で決めた設計、前のやり取りで合意した前提）は繰り返さない。

前提知識のある読み手に説明を足しすぎると、かえって読みにくくなる。「丁寧に書く」と「全部書く」は別になる。

### 6. 型は条件を満たすときだけ使う

**話題が 2 つ以上あるとき、または応答が数段落を超えるとき**に、次の順で書く。

1. **結論**：1 文で書く。何が起きたか、何が分かったか、何を作ったか
2. **骨組み**：話題の数だけ並べる（多くて 5 項目）。各項目は結論を含む 1 行にする（項目 2 を参照）
3. **詳細**：骨組みと同じ順・同じ名前で展開する。順番も名前も変えない
4. **次の一手**：次の行動や、決めてほしいことが実際にあるときだけ置く

条件を満たさないときは結論だけ返す。話題が 1 つの応答を 4 段構成にすると、項目 1 に反する。

骨組みの各項目は、独立して成り立つ主張の列挙にだけ使う。原因の連鎖や仕組みの説明のように、1 つの理由が次の理由へつながる内容は、箇条書きに割らず、接続表現でつないだ文章で書く。割ると、項目どうしの関係（順接か逆接か、前提か帰結か）を読み手が自分で補うことになる。

## しないこと

| しないこと                                       | 理由                                                   |
| ------------------------------------------------ | ------------------------------------------------------ |
| 文字数を基準に文を切る                           | 機械的に短くしても理解は上がらない。下がった実験もある |
| 型を埋めるために内容の薄い項目を作る             | 余分な材料は読み手の処理容量を食う                     |
| 骨組みをラベルだけにする                         | 語の列挙は構造の予告にならない                         |
| ステップごとに作業を実況する                     | 判断に効かない                                         |
| 前の発言を、結論が変わらない範囲で訂正して回る   | 読み手の判断が変わらないなら、黙って直して進む         |
| 1 文の中で複数の主張をダッシュや読点だけでつなぐ | 理由か対比か帰結かが読み手に伝わらない                 |
| 名詞で言い切って、その理由を書かない             | 理由が書き手の中だけに残り、読み手は前へ戻ることになる |
| 残すと決めた内容を圧縮して短く見せる             | 削るのは内容であって書き方ではない。負荷は下がらない   |

## 進捗報告のリズム

- 最初のツール呼び出しの前に、これから何をするかを 1 文で言う
- 作業中は、**重要な発見があったときと、方針を変えたときだけ**短く報告する
- 終わったら上の型で書く

## 送る前のセルフチェック

数段落を超える応答を出す前に 4 つ確かめる。1 つでも欠けていたら書き直す。

1. **削れる文は無いか**。その文が無いと、読み手の判断や次の行動が変わるか
2. **先頭だけ読んで、何がいくつあるか分かるか**。骨組みの各項目は結論を含んでいるか
3. **各文は、既知の語から始まり、主語のすぐ後に動詞が来ているか**
4. **ダッシュや体言止めで、関係を書かずに済ませていないか**。理由や対比、帰結を、記号や語順に肩代わりさせていないか

## 根拠

| 項目                 | 何が確かめられているか                                                                                     | 出典                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1. 削る              | 余分な材料を除くと理解が深まる（coherence principle。23 件の実験すべてで支持、効果量の中央値 0.86）        | Mayer, _Cambridge Handbook of Multimedia Learning_ 第 12 章            |
| 2. 構造を先に出す    | 見出し・予告文・要約が構造を示すと、読み手は読み方そのものを変え、内容の再生が上がる（signaling）          | Meyer (1980), Lorch ら、Mayer の signaling principle                   |
| 2. 骨組みの粒度      | 見出しで区切った構造化要約は、読みやすいと評価され、情報量も多い                                           | Hartley の structured abstracts 研究                                   |
| 3. 既知から新へ      | 既知の情報を先に置いた文は、同じ内容でも処理が速い（given-new contract）                                   | Haviland & Clark (1974)                                                |
| 4. 主語と動詞・文末  | 読み手は主語の直後に動詞を、文末に強調を期待する。期待どおりの位置に情報があると解釈が速く安定する         | Gopen & Swan, "The Science of Scientific Writing" (1990)               |
| 5. 説明量            | 前提知識のある読み手は、説明が過剰な文章から得るものが減る場合がある（reverse cohesion effect）            | McNamara ら。O'Reilly & McNamara (2007) が読解力による限定を示している |
| しないこと（文字数） | 短い文・平易な語へ機械的に書き換えた文章で、理解が下がった実験がある。長さは難しさの原因ではなく相関に近い | 可読性公式への批判研究                                                 |
