# テンプレート同期対象には、プロジェクト固有の内容を書かない

`.claude/` のルール・スキル・設定の一部は、テンプレートリポジトリと双方向に同期され、複数のプロジェクトで共有される。同期対象に特定プロジェクトの事情を書くと、他のプロジェクトへ意味の通らない記述が配られる。受け取った側はそれを直せない。直しても次の同期で書き戻る。

同期対象かどうかは `.ziku/ziku.jsonc` の `include` が決める。ファイルを書く前に、そのパスが `include` にマッチするか確認する。`.claude/rules/*.md` のようなグロブはディレクトリ直下だけにマッチし、サブディレクトリは対象外になる。

## 同期対象には一般化して書く

| 書かない                                         | 代わりに書く                                       |
| ------------------------------------------------ | -------------------------------------------------- |
| リポジトリ名・サービス名・チーム名・ホスト名     | 役割で書く（「サブモジュール」「外部 API」）       |
| そのプロジェクトのディレクトリ構成への依存       | 構成に依存しない条件（「別リポジトリ配下の作業」） |
| 特定ツール・SaaS の固有名                        | 種類で書く（「BI ツール」「エラー監視サービス」）  |
| 社内でしか通じない略語・呼称                     | 一般語に置き換えるか、その場で定義する             |
| そのプロジェクトにしか無い設定・コマンドを前提化 | 「プロジェクトの設定を確認して従う」と条件化する   |

判断基準は **「このプロジェクトを知らない人が、別のリポジトリでこの記述を読んで、そのまま使えるか」**。使えないなら固有の内容が混ざっている。

## 一般化できない内容の置き場所

一般化すると意味が失われる記述（そのプロジェクトでしか成立しない運用、固有ツールの手順、具体的なホスト名）は、同期対象の外に置く。

| 置き場所                      | 何を置くか                                       |
| ----------------------------- | ------------------------------------------------ |
| `.claude/rules/project/`      | そのプロジェクト限定のルール                     |
| `.claude/rules/<領域>/`       | 特定の技術スタック・業務領域に閉じたルール       |
| `.claude/hooks/project/`      | プロジェクト固有の hook スクリプト               |
| `.cursor/rules/project/`      | 上記ルールの Cursor 用ラッパ（プロジェクト限定） |
| `.claude/guides/`             | 手順・調査メモなど、読み込みが任意の資料         |
| `.claude/settings.local.json` | 個人・環境依存の設定（バージョン管理の対象外）   |
| `CLAUDE.md`                   | プロジェクトの全体像と、上記への入口             |

## 骨組みと中身を分けて両立させる

同期対象に骨組みだけを置き、固有の中身を外から差し込む形にすると、共有と固有を同時に満たせる。

- **hook**: 同期対象の設定からは固有ディレクトリ配下をまとめて呼び、スクリプト本体は同期対象外のディレクトリに置く。他プロジェクトではそのディレクトリが空なので何も起きない
- **ルール**: 同期対象には原則と判断基準を書き、そのプロジェクトでの具体的な手段は固有側のルールに書いて相互に参照する
- **マルチエージェント**: hook の正本は `.claude/hooks/manifest.json` と `.claude/hooks/*.ts`。Cursor / Codex 向けの配線と rules ラッパは `pnpm agent-adapters:generate` の生成物（手順は `.claude/guides/tools/cursor.md`）

## テンプレートへ返す前に確認する

同期対象を編集したら、テンプレートへ push する前に差分を読み直し、固有の値（ホスト名・絶対パス・プロジェクト名・認証情報への参照）が混ざっていないか確認する。設定ファイルは特に混ざりやすい。許可リスト・有効化リスト・接続定義の類は、プロジェクトごとに中身が変わる前提で書かれているため、そのまま送ると他プロジェクトへ無関係な項目が配られる。

## 同期対象から外す判断

一般化もできず、骨組みと中身にも分けられないファイルは、`include` から外して固有資産にする。プロジェクトごとに中身が変わる前提のファイル（言語・ツールのバージョン指定、外部サービスの接続定義など）が該当する。

`include` はテンプレート側が正本なので、ローカルで勝手に削るとテンプレートとの差分として毎回検出される。外したいときはテンプレート側へ反映する。
